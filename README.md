# Тесты для аккредитации → Moodle

Сайт, где преподаватели заполняют тесты по своим дисциплинам. Администратор выгружает их в формате Moodle XML и импортирует в банк вопросов Moodle.

## Возможности

- **Вход по логину и паролю.** Один общий вход для преподавателей и отдельный для администратора.
- **Один тест на дисциплину.** У теста указаны дисциплина, преподаватель, который его заполняет, и кафедра. Настройки для Moodle: время, сколько вопросов показывать студенту, попытки, проходной балл, перемешивание.
- **Вопросы.** Основной тип — выбор ответа: преподаватель пишет варианты и нажимает «Верный» у правильных. Один верный или несколько, сайт определяет сам. Остальные типы спрятаны в «Другой тип вопроса»:
  - верно/неверно;
  - ответ словом;
  - ответ числом с погрешностью;
  - соответствие.

  К вопросу можно добавить картинку: кнопкой, через Ctrl+V или перетаскиванием.
- **Вставка из Word.** Тест копируется целиком (Ctrl+A, Ctrl+C), и сайт сам раскладывает его на вопросы и варианты. Верные ответы распознаются по выделению в Word (жирный, подчёркивание, цвет, заливка), по «*» или по строке «Ответ: б». Варианты могут быть с буквами или без.
- **Автосохранение и «Готово».** Всё сохраняется автоматически. Кнопка «Готово» проверяет тест: если что-то не так, показывает вопрос, отмеченный красным, с короткой подсказкой («Отметьте верный ответ»). ФИО и кафедра запоминаются в браузере для следующих тестов.
- **Админка:**
  - архив со всеми тестами: по XML на дисциплину плюс `tests.csv` с настройками;
  - XML отдельного теста;
  - восстановление удалённых тестов;
  - смена паролей;
  - резервная копия базы.

## Защита

- **HTTPS.** Сертификат Caddy получает сам.
- **Пароли.** Хранятся только в виде хэша (scrypt). После смены пароля все старые сессии перестают действовать.
- **Защита от подбора.** После 5 неверных попыток вход с этого адреса блокируется на 15 минут.
- **Защита от сканеров.** Адрес блокируется на 12 часов, если без входа он:
  - запросил путь-ловушку (`/.env`, `/wp-admin`, `*.php`, `/.git` и т. п.);
  - получил больше 8 ответов 404 за 10 минут;
  - отправил больше 60 запросов за минуту.

  Блокировка действует только на запросы без входа, страница входа открыта всегда. Поэтому бот в общей сети университета не лишит доступа преподавателей. Список блокировок и кнопка «Разблокировать» есть в админке (`app/guard.py`).
- **Заголовки безопасности.** HSTS, CSP, `X-Frame-Options`, `Permissions-Policy`, `Cross-Origin-Opener-Policy` и `Cross-Origin-Resource-Policy`. Заголовок `Server` скрыт.
- **Сайт закрыт от поисковиков.** Используются `robots.txt` и `X-Robots-Tag: noindex`. Без входа недоступны ни страницы, ни картинки, ни API.
- **Защита от CSRF и встраивания.** Cookie с `SameSite=Lax`, API требует служебный заголовок, есть заголовки CSP и `X-Frame-Options`.
- **Защита от одновременной правки.** Если тест одновременно правят двое, второй увидит предупреждение, а не перезапишет чужие изменения молча.
- **Удаление обратимо.** Удалённый тест восстанавливается из админки.

## Запуск на сервере

Нужны Docker и Docker Compose, а также открытые порты 80 и 443.

1. **Домен.** Зайдите на [duckdns.org](https://www.duckdns.org) (вход через Google или GitHub), создайте поддомен, например `bstu-tests`, и укажите IP сервера.
2. **Код и настройки:**
   ```bash
   git clone https://github.com/DmitriyKuladmed/MoodleTests2026.git
   cd MoodleTests2026
   cp .env.example .env
   nano .env   # DOMAIN и два пароля
   ```
3. **Запуск:**
   ```bash
   docker compose up -d --build
   ```
   Через минуту сайт откроется на `https://<домен>`.

Обновление: `git pull && docker compose up -d --build`. Данные лежат в томе `app_data` и при обновлении не пропадают.

### Резервные копии

Копию базы можно скачать кнопкой «Резервная копия базы» в админке. Ежедневную копию на сервере удобно сделать через cron:

```bash
0 3 * * * cd /path/to/MoodleTests2026 && docker compose exec -T app python -c "from app.db import Database; from pathlib import Path; Database(Path('/data/tests.db')).backup_to(Path('/data/backup.db'))" && docker compose cp app:/data/backup.db ./backups/tests-$(date +\%F).db
```

### Журнал действий

Приложение записывает в журнал:
- входы, в том числе неудачные, и блокировки;
- создание, сохранение, «Готово» и удаление тестов;
- конфликты одновременной правки;
- загрузку картинок и вставку из Word;
- действия администратора;
- ошибки сервера с трассировкой и ошибки из браузеров: JS-исключения, сбои сохранения, уход со страницы с несохранёнными правками.

Пароли и тексты вопросов в журнал не попадают.

Каждая строка — одно событие с полями `rid` (код запроса), `sid` (сеанс браузера после входа), `role` и `ip`. При ошибке сервера пользователь видит сообщение с кодом `rid`, и по этому коду строку легко найти в журнале.

Где смотреть:
- в админке: «Открыть журнал» (последние строки) и «Скачать журнал»;
- на сервере: `docker compose logs app` или файл `/data/logs/app.log` в томе `app_data` (ротация 10 файлов по 10 МБ).

## Загрузка в Moodle

1. В админке нажмите «Скачать все тесты для Moodle» и распакуйте архив.
2. В курсе Moodle откройте «Банк вопросов», затем «Импорт» и выберите «Формат Moodle XML» и файл дисциплины. Вопросы попадут в выбранную категорию.
3. Создайте тест и добавьте вопросы. Можно «случайные вопросы» из категории: столько, сколько указано в `tests.csv`.

## Разработка

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt   # Windows; на Linux — .venv/bin/pip
cp .env.example .env                                # задайте пароли
.venv/Scripts/python -m uvicorn --factory app.main:build_app --reload --port 8765
.venv/Scripts/python -m pytest
```
